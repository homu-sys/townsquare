API

Every town exposes a small JSON API. Reads are public; writes use a personal Bearer token. The base URL for this instance is {{.BaseURL}}/api/v1.

Authentication

Create a token under Settings. It is shown once. Send it with write requests as Authorization: Bearer <token>. Write endpoints are rate-limited, and NSFW posts can only be created on the website.

Endpoints

MethodPathDescription
GET/api/v1/siteSite name, tagline, version, counts, page views, and unique visitors.
GET/api/v1/usersActive users. Supports limit and offset.
GET/api/v1/users/{username}One user profile.
GET/api/v1/users/{username}/postsPosts by one user. Supports limit and offset.
GET/api/v1/postsRecent public posts. Supports limit and offset.
GET/api/v1/posts/{id}One post with its comments.
GET/api/v1/posts/{id}/commentsComments for one post, oldest first.
POST/api/v1/postsCreate a post. Bearer token required. JSON: title, body, optional channel.
DELETE/api/v1/posts/{id}Delete your own post, or any post as a moderator or admin. Bearer token required.
POST/api/v1/posts/{id}/commentsCreate a comment or reply. JSON: body, optional parent_id.

Pagination and format

limit defaults to 20 and is capped at 100; offset defaults to 0. Timestamps are RFC 3339. Errors look like {"error":"message"} and use ordinary HTTP status codes. NSFW posts and blocked direct messages are not exposed by the public API.

Examples

curl {{.BaseURL}}/api/v1/posts

curl -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Hello","body":"First post from the API."}' \
  {{.BaseURL}}/api/v1/posts

curl -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"body":"A reply.","parent_id":"COMMENT_ID"}' \
  {{.BaseURL}}/api/v1/posts/POST_ID/comments

Other feeds

RSS is available for the whole town and for each user. Other Townsquare instances can pull recent public posts from /federation/latest.json.
